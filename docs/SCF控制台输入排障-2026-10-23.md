## 原因与证据边界

本轮复现：在日志页面，无障碍树仍列出测试编辑器；按该元素点击后，全选实际选中了网页正文，粘贴没有改变 Hello World 测试模板。切回函数管理，滚动到真实可见的事件编辑器，坐标点击、粘贴并全选回读后，内容才与预期一致。同一部署随后 P2 成功。

本次 P4 再次遇到测试编辑器输入不完整并混入旧模板尾部的情况。修复时先在真实可见的编辑器内全选清空，再粘贴完整 JSON；控制台格式化工具最初报 JSON Parse error，因此没有提交。再次按可见控件定位并完整粘贴后，控制台显示“格式化成功”，才允许运行。由此确认：根因是嵌套 Cloud Studio 编辑器的焦点/选择状态与页面无障碍树不同步，导致清空/替换操作没有作用于预期编辑内容；不能简单称为 SCF 函数或平台运行故障。

这证明本轮存在输入焦点/隐藏控件问题，不证明腾讯云编辑器存在产品缺陷，也不能恢复每次历史失败的完整输入。历史 task_id 校验错误只证明顶层 task_id 缺失、为空或过长；不能把它解释为 DeepSeek 超时。逐字键入还可能引入标点和字段名损坏，因此 JSON 优先完整粘贴并回读。

## 通用执行闸门

1. 定义测试目标：单阶段冒烟与全链路验收分开，不临时修改已确认产品决策。
2. 确认当前页面和可见控件。元素出现在无障碍树，不等于可见或已获得输入焦点。
3. 从版本化 JSON 样本读取输入；离线验证 JSON、worker 外层字段和阶段必需参数。
4. 在可见事件框内粘贴，完整回读并比较；必须核对 task_id、stage、attempt、payload。无法回读则不提交。
5. 只点测试，不点部署。保存 Request ID；请求提交成功不等于函数执行成功。
6. 等待终态，核对业务响应 accepted/status/stage/task_id，而不只看绿色提示。
7. 按层定位：界面输入、事件契约、数据库领取、阶段参数、模型调用、结果校验、状态保存。只修改有证据指向的层。
8. 同一 attempt 可能被幂等领取拒绝；not_claimed 不是模型失败。不得为反复测试盲目递增 attempt 或制造无限模型费用。

通俗解释：先确认“寄出的包裹里确实装了正确任务”，再查运输和处理；点击发送只是寄出，拿到匹配的处理结果才算完成。
