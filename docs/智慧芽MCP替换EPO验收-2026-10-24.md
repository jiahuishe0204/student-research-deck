# 智慧芽 MCP 替换 EPO 验收

## 边界

- 只将专利检索从 EPO OPS 切换为中国区智慧芽“全球核心专利库”MCP。
- `PATSNAP_API_KEY` 继续服务于原医学文献 REST API；`PATSNAP_MCP_API_KEY` 专用于专利 MCP。
- 不改动 P1—P9 产物契约、证据筛选、报告/PPT 结构或网页样式。
- EPO OPS 保留为 `PATENT_PROVIDER=epo_ops` 显式回滚通道。

## 运行配置

```text
PATENT_PROVIDER=patsnap_mcp_cn
PATSNAP_MCP_URL=https://connect.zhihuiya.com/1458a4/mcp
PATSNAP_MCP_API_KEY=<server-side secret>
PATSNAP_MCP_TIMEOUT_SECONDS=30
```

密钥只能通过服务端密钥设施注入，不得放入前端、Git 或日志。

## 实施结果

- 实现标准 MCP `initialize` / `notifications/initialized` 握手、会话复用及 JSON/SSE 响应解析。
- 首版每个检索任务只在首条查询上调用一次 `search_patents`，最多返回 3 条书目记录。
- 专利结果映射为现有来源记录，包含专利号、标题、发明人、申请人、日期、法域和智慧芽回链。
- 鉴权、限流、积分不足和响应格式错误均使用专用异常，不泄露密钥。

## 真实账户验收

- MCP 工具列表：20 个只读工具，握手成功。
- 三次 `search_patents` 均成功，每次 20 cr，合计 60 cr；握手和工具列表未计费。
- 完整回归任务 `TASK-681932c941bd` 完成 P1—P9，保存 12 条来源（智慧芽 MCP 3 条）、8 页 PPT 和 75 条主张，高风险遗留为 0。
- 完整任务只新增一次 MCP 专利调用，符合费用上限设计。

## 仓库决策

保留在当前产品仓库，通过环境变量切换专利提供方，不另建一套会与 P1—P9 和网页契约发生漂移的项目。
