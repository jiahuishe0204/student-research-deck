## 一、目标与已确认原则

目标不是简单增加一个登录弹窗，而是建立一条低门槛、成本可控、可恢复、可交付的完整路径：用户先免登录了解产品并输入主题，在真正消耗模型额度或领取完整交付前完成邮箱验证，随后获得一次免费快速版，任务完成后通过站内结果页和邮件安全链接取回成果。

已确认：

1. 首页、案例、价格、来源说明和主题输入允许免登录浏览。
2. 首版使用邮箱验证码，不接手机号短信或微信登录。
3. 新用户首次快速版免费；深入版不纳入首次免费。
4. 报告和 PPT 内容包不默认作为邮件附件，邮件发送任务完成通知和安全下载链接。
5. GitHub Pages继续承担公开作品展示，不承担真实登录、资格判断、模型生成和私密交付。
6. 当前阶段不同时引入支付；先跑通免费体验、成本控制和真实交付。

## 二、推荐的端到端主流程

1. **免登录访问**：查看定位、示例、价格、来源边界和隐私提示。
2. **匿名输入**：填写主题、选择快速版/深入版和可选场景；这些草稿只保存在当前页面内存中。
3. **免费轻处理**：执行不产生或只产生极低模型费用的输入校验、主题规范化和规则判断。
4. **意图确认**：展示系统理解；宽主题提供2—4个方向，只追问一个关键问题。
5. **登录闸门**：用户点击“开始首次免费调研”时输入邮箱验证码；验证成功即创建账号。
6. **资格与风险判断**：检查是否用过首次免费、是否达到频率限制、任务预计成本是否超过快速版硬上限。
7. **任务确认**：再次展示正式题目、交付范围、预计时间、免费/付费状态和数据保存期限。
8. **异步生成**：创建任务后立即返回任务页；后台按 P1—P9 执行，阶段产物持续保存，可暂停、失败续跑。
9. **状态通知**：页面轮询任务状态；用户可以关闭页面。完成、部分完成或需用户处理时发送邮件。
10. **交付领取**：登录后查看报告、PPT逐页内容、来源与核验；安全下载链接短期有效。
11. **历史与删除**：账号页查看任务、重新发送交付邮件、删除任务或账号。
12. **后续复购**：首次免费使用后再展示后续快速版和深入版价格；支付另立决策，不阻塞本功能上线。

### 必须明确的任务状态

- `draft`：匿名输入尚未确认。
- `awaiting_verification`：等待邮箱验证。
- `queued`：已取得资格，等待执行。
- `running`：正在执行，显示真实阶段而非虚假百分比。
- `needs_input`：存在会改变结果的唯一关键问题。
- `partial`：只能交付证据支持的部分内容。
- `completed`：终稿通过质量门禁。
- `failed_retryable`：可从检查点续跑。
- `failed_final`：无法继续，说明原因且不消耗免费资格或恢复资格。
- `cancelled`：用户取消，停止后续模型调用。
- `expired`：交付已超过保存期。

## 三、关键决策节点与选项

### A. 登录闸门放在哪里

**A1 进入首页即登录**
优点：账号和任务关系最简单，防滥用强。
缺点：最高进入阻力，面试官和首次访客无法先理解产品。
结论：不选。

**A2 输入主题前登录**
优点：可以保存所有输入。
缺点：用户尚未看到价值就被要求验证。
结论：不选。

**A3 意图确认后、创建付费模型任务前登录（已确认）**
优点：用户已获得明确反馈；大额模型成本发生前完成身份与资格判断；匿名数据量有限。
缺点：需要把匿名草稿在登录后绑定到账号。
结论：已选定。

**A4 完整生成后、下载前登录**
优点：体验阻力最低。
缺点：未验证用户可消耗完整模型费用，极易被滥用。
结论：不选。

### B. 匿名会话如何保存

**B1 只放浏览器内存**：最简单，但刷新即丢失。
**B2 `localStorage` 保存主题和界面状态**：开发快，但脚本可读取，不适合保存权限凭证。
**B3 服务端匿名会话 + HttpOnly/SameSite Cookie**：安全性和可恢复性最好；需要真实后端和会话表。
**已确认**：选择 B1。匿名输入很短，只保存在当前页面的浏览器内存中；刷新或关闭页面后允许用户重新输入，不为此增加持久化和匿名会话合并复杂度。登录后的账号、任务归属和资格凭证仍由服务端安全保存。

### C. 首次免费到底包含什么

**C1 只看固定示例**：成本最低，但不能验证用户自己的题目。
**C2 免费意图识别和三页规划**：成本可控、转化链短，但与“首次快速版免费”的公开承诺不一致。
**C3 一次完整快速版**：价值最清楚，最适合验证真实需求；必须有邮箱验证、成本硬上限和限流。
**C4 赠送可拆分额度**：最灵活，但用户难理解、计量复杂。
**已确认**：C3；每个已验证邮箱一次完整快速版。证据不足时如实交付 `partial`，技术失败不扣除资格。

### D. 邮箱登录方式

**D1 六位数字验证码**：跨设备和移动端输入直观；需要验证码存储、过期、尝试次数与重发限制。
**D2 Magic Link**：点击即可登录；邮件可能在另一设备打开，回跳和链接安全更复杂。
**D3 邮箱+密码**：成熟但增加注册、找回密码和密码安全负担。
**已确认**：首版 D1。验证码10分钟有效、单次使用、最多5次尝试、60秒后重发；验证码只保存哈希。

### E. 首次免费资格怎样判断

**E1 只按邮箱**：规则清楚，开发最简单；可用多个邮箱重复领取。
**E2 邮箱为主，叠加设备/IP风险信号**：兼顾体验与防滥用；存在校园网多人共用IP，不能仅凭IP封禁。
**E3 必须教育邮箱**：防滥用较强，但中国高校邮箱覆盖和使用习惯不统一。
**E4 人工体验码**：适合封闭内测，不适合公开自助体验。
**已确认**：使用 E1，只按已验证邮箱判断首次免费资格，每个邮箱一次。IP仍可用于接口安全限速，但不参与免费资格判定，也不使用设备指纹否定资格。该方案简单、对校园网用户公平，但接受用户通过多个邮箱重复领取的风险；若真实滥用明显，必须重新取得用户确认后才能升级规则。

### F. 前端和后端部署

**F1 GitHub Pages + 独立 API**：保留现有展示页，开发改动较少；跨域、Cookie、国内访问和私密任务处理更复杂。
**F2 前后端同域部署**：Cookie、安全链接和接口最简单，适合真实产品；需要新的运行环境。
**F3 中国内地云部署**：国内访问最好；域名、备案和合规准备更多。
**F4 香港/海外近中国区域**：启动快、无需等待内地备案；国内网络稳定性需真实测试。
**已确认**：真实内测站采用 F2。用户访问现有腾讯云 EdgeOne 免费层上的同域网页和 API 入口；后台 P1—P9 任务由腾讯云独立云函数 SCF 执行，不新增面向用户的网站。现有 EdgeOne 同域静态站、Cloud Functions、Blob 和创建者登录可继续复用；新增普通用户邮箱登录、权益和任务 API。EdgeOne Cloud Functions 单次最多 120 秒，不承担完整长任务。GitHub Pages继续作为公开作品展示。

### G. 后端形态

**G1 在当前 Python 服务中直接增加账号、任务和邮件模块**：继承现有 P1—P9，改造最少；要补数据库迁移、生产服务器和安全中间件。
**G2 无服务器函数拆分**：弹性好；长任务、超时、调试和多阶段状态编排复杂。
**G3 托管身份平台 + 当前工作流后端**：身份安全负担较低；增加供应商依赖，仍需自己的资格和任务数据库。
**已确认**：G1 为主，扩展现有 Python 服务，身份实现保持模块化；将后台执行部分适配到腾讯云独立 SCF，不把完整 P1—P9 塞进 EdgeOne 的单次短时请求。现有 EdgeOne 创建者登录的 HttpOnly Cookie、会话过期、限速和审计设计可以参考，但单一管理员的密码+TOTP账号不能直接替代多用户邮箱验证码体系。

### H. 数据库和任务队列

**H1 SQLite**：本地测试简单；多进程、备份和云部署限制明显。
**H2 托管 PostgreSQL**：事务、唯一约束、审计和扩展性好；免费额度以外可能产生服务成本，也需要运维配置。
**H3 云厂商文档数据库**：接入某些云函数方便；关系型订单、资格和任务状态约束较弱。
**已确认**：使用 H2 托管 PostgreSQL，内测先使用免费额度；具体 PostgreSQL 服务商尚待比较确认。本地测试允许 SQLite适配层。首版使用数据库任务表 + 独立 worker，验证并发后再决定是否增加 Redis/专业队列。

**内测成本决定**：完整内测先使用 PostgreSQL 免费额度，具体供应商仍待比较后确认。免费额度不是“永久零成本”承诺；容量、休眠、连接数、出站流量、备份和超额策略必须在选型时逐项验收，并设置额度提醒和迁移出口。

### H4. MVP 后台 worker 的运行位置与恢复方式

**已确认的运行位置**：腾讯云独立云函数 SCF。选择目的是在 MVP 阶段使用新用户前三个月的免费额度进行完整内测；该额度是否适用于当前腾讯云账户、从何时开始计算、以及外网流量与日志等其他计费项，必须在开通或部署前从控制台核实。此决定只覆盖 MVP，不预先决定免费期结束后的运行平台。官方计费说明：https://cloud.tencent.com/document/product/583/17299 。

**待技术验证的执行方式**：优先评估 SCF 的异步执行。EdgeOne 接到用户请求后创建任务并写入 PostgreSQL，随后触发 SCF；SCF 从数据库原子领取任务，按 P1—P9 保存检查点、更新进度，完成后发邮件。SCF 官方异步执行文档说明调用方可先拿到 RequestId、函数最长可运行24小时，但执行失败不提供可配置的自动重试；因此仍必须由任务状态、租约超时和恢复机制处理重试，不能仅依赖云函数自身。文档：https://cloud.tencent.com/document/product/583/51519 。实际触发接口、函数资源规格、Python 依赖打包、网络连通及最长耗时在技术验证后确定。

### I. 用户怎样看到进度

**I1 同步等待单个请求**：实现简单；完整研究容易超时，关闭页面即失联。
**I2 页面定时查询**：可靠、兼容性好；会产生少量查询请求。
**I3 SSE/WebSocket实时推送**：体验更实时；连接与部署复杂度更高。
**I4 只发邮件**：实现较少；用户没有过程可见性。
**已确认**：I2 + 完成邮件。页面显示真实阶段、最后更新时间和可安全关闭页面的提示。

### J. 报告和PPT如何交付

**J1 邮件附件**：用户直观；大附件、版本过期、转发泄露和送达率问题明显。
**J2 邮件安全链接**：邮件轻、可过期、可撤销、始终指向最新版；需要对象存储或登录后动态导出。
**J3 只在站内查看**：控制最强；用户容易错过完成通知。
**已确认**：J2 + J3。邮件只发送完成通知和短期安全链接，不把报告正文或大附件直接放进邮件；用户点击链接后，在站内登录并安全查看最新版结果。首版导出 Markdown/PDF候选，PPTX继续后置。小规模内测可使用邮件、存储和流量免费额度，通常不会新增现金支出，但会增加链接令牌、过期、撤销、权限校验和邮件送达处理的开发工作；超过免费额度后可能产生费用。

**内测成本决定**：验证码、完成通知和到期提醒先使用事务邮件服务的免费额度。具体服务商仍待确认；选型必须同时检查中国大陆送达率、发信域名验证、每日/月度额度、退信处理和超额后是否自动收费。

### K. 文件保存与删除

**K1 永久保存**：用户方便，但隐私、成本和责任最大。
**K2 完成后30天自动删除交付文件**：风险较低，用户仍有领取时间。
**K3 用户自选7/30/90天**：灵活，但规则和界面更复杂。
**已确认**：交付文件默认保存7天，到期前1天邮件提醒，用户可提前删除。账号、首次免费资格和最低必要审计记录采用独立保存期限，不能随交付文件一起删除，否则无法防止重复领取。

### L. 技术失败与免费资格

**L1 一创建任务就扣资格**：最容易实现，但用户承担系统失败。
**L2 完成交付后扣资格**：公平，但失败任务可能被无限重试。
**L3 运行时预占、成功后核销、技术失败释放**：状态最准确；实现稍复杂。
**已确认并简化为三条规则**：创建任务时预占资格；平台技术失败且没有可用交付时自动释放；完成交付或因真实资料不足形成可阅读、明确披露边界的 `partial` 时核销一次。错误原因由程序错误码分类，不交给用户或模型自行选择。

### M. 支付何时进入

**M1 与免费体验同时开发**：流程一次完整，但显著扩大范围。
**M2 免费体验稳定后再接支付**：更快验证需求，减少退款和订单复杂度。
**M3 先人工收款/体验码**：适合极小规模访谈，但不适合公开自助产品。
**已确认**：M2；数据模型预留订单和权益，但本轮不接真实支付。免费体验、成本和质量稳定后再接支付。

## 四、推荐的首版技术边界

### 本轮必须做

- 免登录浏览、输入与匿名草稿。
- 意图确认后的邮箱验证码闸门。
- 账号、会话、验证码、首次免费权益和任务归属。
- 数据库任务队列和独立 worker。
- 真实阶段查询、失败恢复和取消。
- 完成邮件、安全交付链接、历史任务页和删除入口。
- 单任务成本硬上限、邮箱/IP频率限制和最小审计日志。
- 隐私说明、保存期限、服务边界和错误文案。

### 本轮明确不做

- 微信、手机号、密码登录和多因素认证。
- 真实支付、自动退款和发票。
- 直接生成 `.pptx`。
- 多设备实时同步编辑。
- 机构管理员和多人协作。
- 复杂会员、积分、优惠券和邀请裂变。

## 五、最小数据模型

- `users`：邮箱规范化值、邮箱哈希/加密值、验证时间、状态、创建时间。
- `sessions`：已验证用户会话、过期时间、撤销时间、最近活动；B1 匿名草稿不建立服务端会话。
- `email_challenges`：用途、验证码哈希、过期时间、尝试次数、发送次数、消费时间。
- `entitlements`：首次免费快速版权益、预占任务、核销/释放时间和原因。
- `tasks`：用户、匿名来源、主题、版本、状态、当前阶段、成本上限、取消时间。
- `task_events`：阶段事件、时间、可公开消息、内部错误码。
- `artifacts`：报告/PPT/来源/核验版本、存储位置、保留到期时间。
- `delivery_links`：随机令牌哈希、任务、用途、过期和撤销时间。
- `email_deliveries`：验证码/完成通知、服务商消息ID、投递和退信状态。
- `risk_events`：限速键、IP哈希、设备信号、触发规则和处置。
- `audit_logs`：安全和后台操作，不保存报告正文或验证码明文。

## 六、安全与隐私基线

1. 登录会话使用 `Secure + HttpOnly + SameSite` Cookie；不把登录令牌放在 `localStorage`。
2. 验证码、会话令牌和下载令牌只存哈希；所有密钥只在服务端。
3. 邮箱按展示、查询、防滥用三种用途分别做加密、规范化和不可逆哈希。
4. 登录、发码、验证、建任务、下载和删除都做限速与审计。
5. 下载链接使用高熵随机值、短有效期、单任务范围，可随时撤销。
6. 错误提示不泄露某邮箱是否已经注册；后台日志不记录验证码、Cookie、完整报告或API密钥。
7. 模型任务在启动前执行权益预占和成本预算；达到硬上限自动停止并保存已有结果。
8. 用户可查看保存期限、提前删除任务，并申请删除账号。

## 七、分阶段实施顺序

### 阶段0：逐项冻结规则

核对已确认的登录闸门、免费范围、保存期限、失败扣资格规则及 EdgeOne + SCF 部署边界；继续比较尚未选定的 PostgreSQL 与邮件服务商。

### 阶段1：生产基础设施

复用腾讯云 EdgeOne 免费层的内测域名、HTTPS和同域入口，配置腾讯云独立 SCF worker、托管 PostgreSQL、对象存储和密钥管理；保留GitHub Pages作品展示。

内测阶段采用“免费额度优先”：网页和入口使用腾讯云 EdgeOne 免费层，后台任务使用腾讯云独立 SCF 的新用户三个月免费额度（以当前账户实际资格为准），PostgreSQL 和事务邮件尽量使用免费层，先完成全流程验证。各项额度与模型 API 费用分别统计；免费期结束前依据内测数据决定 SCF 续用、升级或迁移。

### 阶段2：匿名浏览与草稿

实现当前页面内存中的匿名主题输入、意图确认、隐私提示和登录闸门；刷新后允许重新输入，本阶段不触发完整生成。

### 阶段3：邮箱验证码与账号

实现发码、验证、会话、退出、登录后保存已确认主题、历史页空状态和安全测试。

### 阶段4：首次免费权益

实现权益预占/核销/释放、邮箱唯一资格、接口安全限速、成本硬上限和后台查询；不使用IP或设备信号改变首次免费资格。

### 阶段5：异步任务与邮件交付

将现有 P1—P9 适配至腾讯云独立 SCF worker；实现数据库原子领取、检查点、超时恢复、页面轮询、完成邮件、安全链接、下载和7天删除任务，并在到期前1天提醒。

### 阶段6：封闭内测

先由面试展示与少量受邀学生运行；监控激活率、完成率、单任务有效成本、失败损耗、邮件送达和删除流程。

### 阶段7：是否接支付

只有免费流程稳定、跨主题质量通过、成本边界明确后，才冻结价格、退款和支付方案。

## 八、验收清单

- 未登录用户可以完成浏览、输入和意图确认，不被提前打断。
- 创建完整免费任务前必须验证邮箱；匿名输入在刷新或关闭页面后可以丢失，邮箱验证并创建任务后，已确认主题必须由服务端保存且刷新不丢失。
- 同一邮箱最多拥有一个可核销的首次免费权益；并发请求不会重复创建任务。
- 技术失败会释放权益，已交付的 `partial` 按确认规则核销。
- 页面关闭后任务继续，重新登录能看到真实状态和最后成功检查点。
- 邮件不包含报告正文或长期公开链接；链接过期、撤销和越权访问均失败。
- 用户删除任务后无法继续下载，后台只保留规则要求的最小审计记录。
- 任务达到模型费用硬上限后停止，不继续产生不可控费用。
- 邮件退信、任务失败、worker重启、数据库短暂故障均有明确状态和恢复路径。
- GitHub Pages演示与真实内测站文案清楚区分，不误导面试官或用户。

## 九、建议的逐项沟通顺序

1. 首次免费完整范围与失败扣减规则。
2. 登录闸门出现位置和匿名草稿体验。
3. 邮箱验证码交互与邮件服务商。
4. 真实内测站部署区域、域名与后端形态。
5. 数据库、worker、对象存储和保存期限。
6. 任务状态、进度页、取消和失败恢复。
7. 邮件通知、安全链接和下载格式。
8. 防滥用阈值、成本上限和后台能力。
9. 隐私条款、数据删除和客服处理。
10. 内测指标与支付进入条件。

## 十、结合现有工程的实施估时

现有优势是 P1—P9 本地链路、检查点恢复、成本停止器、EdgeOne 同域站点、Cloud Functions、Blob 和创建者登录安全骨架已经存在；主要新增工作集中在多用户身份、PostgreSQL、后台 worker、首次免费权益和线上交付。

- 运行环境与部署样板：1—2个工作日。
- PostgreSQL 数据模型、迁移和存储适配：2—3个工作日。
- 匿名会话、邮箱验证码和账号会话：2—3个工作日。
- 邮箱唯一资格、接口安全限速、权益预占/核销/释放：1—2个工作日。
- P1—P9 后台 worker、数据库队列、定时查询和断点恢复：3—5个工作日。
- 完成邮件、登录后任务链接、7天清理和提前1天提醒：1—2个工作日。
- 集成、安全、异常、部署和真实环境验收：3—5个工作日。

可演示的封闭内测版本预计8—12个专注工作日；把免费全流程做到可供少量真实学生稳定使用，预计15—20个工作日，通常对应3—4个日历周。邮箱发信域名验证、云资源开通、DNS/证书和平台审核可能增加2—5天等待，但其中大部分可以与开发并行。该估时不包含真实支付、自动退款、PPTX和机构后台。
