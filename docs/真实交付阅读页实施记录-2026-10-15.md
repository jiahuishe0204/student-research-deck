# 真实交付阅读页实施记录（2026-10-15）

## 范围与边界

本轮只实现真实交付的本地阅读、浏览器交互与静态只读样本投影，没有修改 `identity_store.py`、`task_store.py`、`server.py` 或 `config/product-decisions.json`，也没有接入邮箱验证码、会话、首次免费资格、支付或后台任务调度。未调用付费模型，未部署或开放线上入口。

阅读页明确区分三类状态：完整阅读、复制和 Markdown 下载为本地可用；内容是仓库中已保存并经人工学术润色的真实验证稿；邮箱登录、线上任务和到期提醒仍待接入。页面不把本地可用表述为已上线，也不把人工润色样本归为自动生成质量。

## 实现结果

- 新增 `web/delivery.html`、`web/delivery.css` 与 `web/delivery.js`，形成独立的完整交付阅读入口。
- 将 `docs/验证稿-慢性植入神经接口-调研报告.md` 与 `docs/验证稿-慢性植入神经接口-PPT内容包.md` 逐字投影到 `web/sample-delivery/`，浏览器读取真实完整内容，不再只依赖首页硬编码节选。
- 报告支持章节目录与正文内原文链接；PPT 支持 12 页逐页切换，并分开展示上屏文字、配图建议与图源、专业答辩式讲稿和本页来源。
- 引用与图源视图对 URL 规范化去重，整理出 6 个论文入口与 5 个原文图页；图页持续提示许可需核对，不自动嵌入。
- 当前报告、当前 PPT 页或引用清单均可复制，并通过统一“下载”菜单选择格式。首页案例区增加“阅读完整本地交付”入口。

## 工程化问题：普通 Windows 用户的交付格式

问题：原“下载当前内容 .md”把 Markdown 暴露为唯一格式。Windows 通常能用记事本打开 `.md`，但普通用户看见的是源码，不一定安装 Typora、MarkText 或 VS Code，因而“文件已下载”不等于“交付可直接阅读”。

验收目标：

1. 主按钮只显示“下载”两个字，点击后再选择格式。
2. Markdown 保留可编辑原文；HTML 为单文件并可由 Windows Edge/Chrome 直接打开；PDF 使用系统打印能力，可选择“另存为 PDF”或“Microsoft Print to PDF”。
3. HTML/PDF 只包含当前报告、当前 PPT 页或当前来源视图，不夹带页面导航和操作按钮，并保留样本、许可与未上线边界。
4. 格式菜单支持鼠标、键盘上下键、Escape 关闭和点击外部关闭；390 px 手机视口无页面级横向溢出。
5. 不引入远程脚本或付费服务，不修改身份、任务、服务入口和产品决策公共文件。

实施：将当前内容入口改为“下载”，提供 Markdown、HTML 和 PDF 三种格式。HTML 使用内联样式生成独立 UTF-8 文件；PDF 不伪造直接下载，而是打开专用打印版并调用浏览器打印窗口，由 Windows 或浏览器保存为 PDF。后续发现独立的“下载完整样本 .md”与统一下载入口重复，且容易制造第二套交付的错觉，因此移除，只保留当前所见内容的单一下载入口。

## 问题、根因与修复

1. **PPT 配图建议被并入上屏文字。** 根因是原验证稿同时存在“标签独占一行”和“标签后紧跟正文”两种格式，初版解析器只识别前者。已让分段规则同时接收两种格式，并在第 1 页和第 12 页复核四个内容层级均完整出现。
2. **同一论文被统计为两个来源。** 根因是同一 Europe PMC 地址在不同位置有带尾斜杠和不带尾斜杠两种写法。已在客户端规范化 URL 后去重，来源入口由 12 个修正为 11 个。
3. **引用卡片只有数字或“原文”，扫描性差。** 根因是正文的 Markdown 链接标签面向行内引用，不适合作为独立来源标题。已从报告参考文献段落提取完整书目信息作为卡片标题，图源使用原文图号。
4. **标签下划线贴近操作框且切换生硬。** 根因是下划线原先是每个标签按钮自身的底边框，只能瞬间显隐；手机布局中标签行与复制/下载行之间也缺少独立间距。已改成根据当前标签宽度与位置移动的独立紫色指示条，移动时同步改变宽度；报告、PPT 与来源内容按切换方向先退出再滑入。手机端在指示条与操作框之间增加 14 px 间距，系统开启“减少动态效果”时取消动画。
5. **结果页被能力说明抢占首屏。** 顶部原有“真实内容样本 / 人工学术润色”、内容统计和“你正在查看什么”状态卡，用户需要先读产品状态才能看到交付。已移除整段说明与顶部状态横幅，把页面收敛为紧凑题目栏和报告、PPT、引用三个结果入口；“邮箱登录 · 待接入”移到右上角。人工润色、许可和未上线边界只在页面底部保留，不打断结果阅读。
6. **Safari 直接打开本地 HTML 时正文为空。** 根因是原页面运行时使用 `fetch()` 读取相邻 Markdown；通过本地 HTTP 服务预览可用，但 Safari 等浏览器会限制 `file://` 页面读取其他本地文件。新增由两份验证稿确定性生成的 `web/sample-delivery/data.js`，页面优先读取这个同页脚本数据包，HTTP 环境仍保留 Markdown 请求作为后备。同步回归会同时比较 Markdown 副本、JavaScript 数据包与源验证稿，避免三个版本漂移。
7. **首屏辅助链接和雪花符号不符合结果页语气。** 已移除左上角“跳到交付正文”链接；品牌图标从白色雪花符号改为蓝紫底上的白色打开书页线性图标，更直接表达报告阅读与知识交付。

## 验证记录

- 通过本地服务实际载入完整报告，识别 9 个一级报告章节、12 页 PPT 和 11 个不重复原文入口。
- 浏览器实际切换报告、PPT 与引用/图源三个视图；检查 PPT 第 1 页和第 12 页，均包含上屏文字、配图建议与图源、专业答辩式讲稿和本页来源。
- 在 390 × 844 手机视口检查报告、PPT 末页和来源列表，`scrollWidth` 与 `innerWidth` 均为 390，没有页面级横向溢出。
- 浏览器复制按钮写入完整 Markdown；当前内容与完整样本下载按钮均执行浏览器原生 Blob 下载并给出正确文件名反馈。自动化浏览器没有报告底层下载事件，因此下载结果仍需在普通浏览器做一次人工落盘复核，不能将本轮记录表述为跨浏览器下载验收。
- 原样本投影与两个 `docs/` 源文件使用文件差异检查，内容一致。
- 增加交付阅读页离线回归，固定检查样本与源文件一致、9 个报告一级章节、12 页完整 PPT 字段、6 个论文入口与 5 个图源，以及本地/样本/待接入状态文案。
- 新增回归后全量本地测试为 177 项通过；产品决策契约与差异空白检查通过。
- 完成多格式下载后全量本地测试为 178 项通过。浏览器实测主按钮仅显示“下载”，菜单包含 Markdown、HTML、PDF；Escape 可关闭菜单，HTML 下载给出 `.html` 文件名及 Windows 浏览器提示；390 px 下 `scrollWidth` 与 `innerWidth` 均为 390，控制台无错误。PDF 已检查 A4 打印样式、操作按钮剔除和能力边界文案；最终选择打印机及保存位置仍由用户在系统打印窗口完成。
- 完成标签动效后全量本地测试为 184 项通过。390 px 浏览器实测指示条与操作区间距为 13 px（CSS 设定 14 px，含边框取整）；从报告切到 PPT 时指示条左侧位置由 33 px 平滑移动到 105 px，宽度由 52 px 调整为 80 px，并正确显示 PPT 第 1 页。继续切换来源时，在动画中间帧读到正文区域非零水平位移，最终标题为“引用与图源”；页面宽度仍为 390 px，控制台无错误。
- 精简结果首屏后全量本地测试为 191 项通过，并同步了并行科学质量任务更新后的最新 PPT 验证稿。浏览器实测顶部说明区和状态卡均不存在，右上角为禁用状态的“邮箱登录 · 待接入”，首个内容标题直接为交付题目并默认显示调研报告；390 px 下结果卡距离页面顶部 112 px，页面宽度无溢出，控制台无错误。
