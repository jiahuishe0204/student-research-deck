# 智慧芽 MCP 替换 EPO 实施与验收

## 目标与边界

- 比赛版只将专利检索提供方从 EPO OPS 切换为中国区智慧芽“全球核心专利库”MCP。
- 原 `PATSNAP_API_KEY` 继续服务于医学文献 REST API，与 `PATSNAP_MCP_API_KEY` 完全分离。
- 不改动 P1—P9 产物契约、证据筛选标准、报告/PPT 结构和网页样式。
- EPO OPS 代码保留为显式回滚通道，不在比赛版默认路径中使用。

## 已实施

1. 新增只读智慧芽 MCP 适配器，固定到已核验的中国区 MCP 地址。
2. 实现标准 MCP `initialize` / `notifications/initialized` 握手与会话复用。
3. 首版每次专利检索只调用一次 `search_patents`，最多取 3 条，仅作书目级证据。
4. 统一专利结果为现有来源记录格式，包含专利号、标题、发明人、申请人、公开/申请日期、法域和回链。
5. 检索层与服务器层改为通用专利提供方，保留旧 `epo_client` 调用兼容。
6. 健康检查会显示当前专利提供方，但绝不返回密钥。
7. 运行版本指纹纳入 MCP 适配器，避免部署后仍显示旧版本。

## 配置

```text
PATENT_PROVIDER=patsnap_mcp_cn
PATSNAP_MCP_URL=https://connect.zhihuiya.com/1458a4/mcp
PATSNAP_MCP_API_KEY=<QQ 账户的 MCP 密钥>
PATSNAP_MCP_TIMEOUT_SECONDS=30
```

`PATSNAP_API_KEY` 保持原值，不得用 MCP 密钥覆盖。若需紧急回滚，将 `PATENT_PROVIDER` 设为 `epo_ops`。

## 上线门槛

1. `tools/list` 能在 QQ 账户密钥下成功，并且不暴露密钥。
2. 一条最小 `search_patents` 调用返回 1—3 条可解析专利，同时在智慧芽用量页可见对应消耗。
3. 使用一个旧题和一个新题完整跑 P1—P9，无结构验证错误。
4. 比较替换前后的来源数、专利数、引用可点击率、引用覆盖率和主张核验状态；任一指标明显退化即不上线。
5. 在现有网页检查报告、PPT 逐页内容、讲者注释、参考文献和专利回链，不允许布局或文案风格漂移。
6. 先部署预发/本地验收，再更新生产环境变量；发生鉴权、限流、积分不足或响应结构变化时立即回滚。
