# 智能工作流与模型路由

版本：v0.2｜日期：2026-10-05

当前实现补充：P1—P9 均已绑定独立 JSON Schema。P3—P9 的输出通过无第三方依赖的统一契约校验器检查，缺少必填字段、出现未定义字段、类型或枚举错误时会被拒绝，不进入下一阶段。

## 1. 是否需要意图识别与规划

需要，但不应把它们做成两个无条件高成本的独立长调用。

原因：用户输入往往只是老师的一句话。若一开始误判了交付场合、听众、篇幅或研究重点，后面再便宜的执行也只会更快地产生错误结果。意图识别和规划是高杠杆节点，值得使用更强推理能力；资料格式化、去重、字段补全和按既定结构写作则适合更便宜的模型或确定性程序。

推荐做法是“重要节点升级，常规节点降级”，并按复杂度动态路由。

## 2. 工作流

### 节点 0：输入安全与基本校验

- 程序完成长度、空输入、恶意内容和重复提交检查。
- 不调用昂贵模型。

### 节点 1：意图识别

- 识别场合、听众、交付物、时长、深度、截止时间和可能的隐含约束。
- 简单明确输入可使用经济模型；模糊、跨领域或多个交付目标时升级强推理模型。
- 输出结构化 JSON，并生成一句话供用户确认。

### 节点 2：调研与汇报规划

- 确定需要回答的核心问题、检索子题、比较维度、证据类型和 PPT 叙事顺序。
- 这是最值得使用强推理模型的节点之一。
- 快速版可以把节点 1 和节点 2 合并成一次调用；深入版分开执行并做一次自检。

### 节点 3：检索与证据处理

- 检索由真实数据接口和程序完成。
- 术语扩展、候选摘要筛选可用经济模型批处理。
- DOI/PMID 去重、URL 白名单、字段校验尽量使用程序，不浪费模型调用。

### 节点 4：内容生成

- 按规划生成调研正文、PPT 逐页内容和演讲者注释。
- 快速版使用经济模型并限制上下文；深入版对关键比较与结论使用强模型。

### 节点 5：高风险核验

- 涉及数字、优劣比较、因果、监管、临床效果和“首次/最好”等结论时升级强模型复核。
- 普通描述、格式转换和语气润色用经济模型。
- 程序检查引用编号、链接、来源存在性和预算。

### 节点 6：PPT 内容编排

- 根据报告生成总体叙事、逐页标题、页面要点、视觉建议和演讲者注释。
- 若规划已经明确，可用经济模型完成；出现页间重复、逻辑跳跃或超时长时，再调用强模型做结构修订。

## 3. 路由原则

- 按节点重要性，而不是按用户是否“高级”机械切换整条链。
- 强模型用于早期方向判断和末端高风险复核；经济模型用于规模化执行。
- 确定性校验交给程序，避免让模型重复做机器更擅长的事。
- 快速版也必须在意图不清或证据高风险时自动升级，不能为了省钱稳定地产生错误结果。
- 深入版获得更多规划、反证和复核预算，但不等于每一步都调用最贵模型。

## 4. 复杂度升级条件

满足任一条件时升级意图或规划模型：

- 输入少于 12 个有效汉字且缺少明确对象。
- 同时要求报告、PPT、竞品、实验方案等三个以上交付物。
- 涉及两个以上学科或技术路线。
- 用户提供的主题与场合冲突，例如“3 分钟汇报”却要求系统综述。
- 需要比较方案、给出推荐或预测趋势。
- 深入版订单。

满足任一条件时升级核验模型：

- 结论涉及安全性、疗效、获批、因果或精确数字。
- 来源互相冲突。
- 只读取摘要却试图给出强结论。
- 企业声明被用于证明效果或优越性。
- 引用核验首次未通过。

## 5. 成本控制

- 记录每节点的模型、输入/输出 tokens、缓存命中、重试和估算成本。
- 下单时按版本预留成本；达到任务预算 80% 时降级非关键润色，不降级引用真实性。
- 快速版优先复用同一份证据生成报告与 PPT，不重新检索。
- 演讲者注释从逐页要点生成，不重复传入全部原始资料。
- 模型名称和价格写入配置，不在提示词里写死。

## 6. 推荐决策

首版采用混合路由：快速版合并“意图识别+规划”为一次强模型调用；深入版拆为两次强模型调用。后续执行默认经济模型，只有高风险结论和失败复核升级。它比“全程强模型”省钱，也比“全程便宜模型”更能避免方向性返工。
