## 4. 故障脉络：事实、推断、待查

### 已有代码和聊天证据支持的发现

1. 邮箱验证码验证成功只表示身份认证完成；新任务还要创建生产任务、检查首次免费资格、写入数据库队列并被 Worker 领取。任一边界失败都会表现为“登录好了，后续没有生成”。
2. `production_task_queue.py` 的任务创建逻辑要求 `free_entitlements.state='available'`。如果资格已被预留/消耗，后端拒绝创建任务。`e8d6326` / `81ec75e` 为此补充了前端解释；这只是错误说明，不会自动恢复资格。
3. 聊天中的腾讯云日志定位到 P2A `ModelOutputTruncated`。当时线上旧包的 P2A/P2B 输出上限报告为 2,800/3,400，而更新源码为 4,200/7,500。聊天将其归因于先前仅把部分修复文件补入旧 ZIP、漏带规划阶段修复。该解释由部署聊天报告，仍应对照实际包清单和线上构建 SHA。
4. `TASK-b2edfe478489` 的进度观察并不一致：一个检查点报告 P3 通过并排入 P4；随后另一个检查点发现 Worker 定时触发但返回 `accepted:false, reason=empty`，页面显示阶段状态不一致。聊天之后又报告恢复 P2 并继续观察，但最终未拿到 P8/P9、COS 发布和下载的完成证据。
5. 旧聊天频繁返回 `{"detail":"Bad Request"}`，属于 Codex 会话自身的系统错误。上下文/浏览器工具输出过大是可能解释之一，但系统未提供明确根因；不能把它记成腾讯云函数错误，也不能据此断言任务失败。

### 仍需验证的假设

- 同一任务页面与 Worker 看见不同阶段，可能涉及失败恢复后数据库 job 状态/可领取条件不匹配、Worker 查错队列/部署包与 API 版本不一致，或仅是读取时点不同。尚无当前数据库行、Worker 响应关联 ID 和部署指纹来区分这些情况。
- 免费资格失败可能影响邮箱验证后的新任务创建；P2 模型截断和 Worker `empty` 则影响已经创建的任务。它们是不同故障点，不应合并成一个“邮箱问题”。
- 最近的代码改动是否已同时部署到 EdgeOne 和所有相关 SCF 函数，目前未知。
