## 问题与处理记录

1. **本机服务连接误判**：受限执行上下文中访问 `127.0.0.1:4180` 曾返回连接失败；获准检查后发现 4180 已有健康服务。没有停止或重启该用户服务，而是另起 4181 实例，并明确设置 ¥3 费用上限。原因是 sandbox 的本机端口访问限制不能等同于应用未启动。

2. **P1 主题需要收窄**：P1 将宽主题识别为需要澄清，安全护栏阻止自动代选。用户选择“单细胞转录组解析肿瘤免疫微环境异质性”后，使用同一个保存任务恢复。方法：凡是影响研究结论范围的选择必须由用户确认；技术性故障则由执行者处理。

3. **P2B Pro 响应反复截断**：两个独立服务实例上，P2B Pro 均出现 `IncompleteRead(0 bytes read)`，累计四次传输失败；P2A Pro 结果完整且可缓存。将 P2B（把已确定的研究框架整理成问题与检索计划）路由到 Flash，保留 P2A Pro 负责学术框架；路由测试通过。这样把强模型留在真正决定研究边界的环节，并避免在同一失败链路重复调用。

4. **P4 上游 TLS 短暂断连**：证据抽取第一次遇到 `SSLEOFError`。无凭据 HTTPS 探测中，系统代理和直连均能到达 API 域名（返回预期的 401），因此没有证据表明是本机代理永久配置错误。利用已保存的 P2/P3 检查点重试 P4，成功完成后继续；不重跑已成功阶段。

5. **P8 内部 token 门限与用户要求不符**：实例最初设为 120,000 tokens，核验到部分批次时触发预算拒绝。用户此前要求该测试主题不限 tokens，因此改为不设总 tokens 上限；¥3 费用上限继续保留。运行后高峰价估算仍为 ¥1.3919。

6. **P8 高风险核验输出被截断**：一条 Pro 核验在 2,200 输出 tokens 处达到模型上限。将高风险核验单次输出预算的下限提高至 3,200、上限提高至 4,800，并增加单测。恢复后 P8 共 19 个外层检查批次全部完成；重复的已完成批次按检查点复用。

7. **P9 重叠声明导致误判无法定位**：P7 将同一报告原句拆为 CLM-0013 和 CLM-0014。第一条修订了整句，第二条再处理时原句已被替换；旧逻辑只用原子声明回查不可变原稿，导致误报并拒绝 P9。修复为保留每条声明的不可变原文用于回退定位，并把追加的核验修订标记为已落实；新增重叠声明测试。修复后无需重跑 P8，P9 确定性装配成功。
