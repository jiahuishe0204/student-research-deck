# 新界面任务交接（2026-10-15）

## 本轮目标

为本科生和研究生使用的科研调研交付产品设计、实现并验证新的用户交互界面与视觉体系。先以真实交付样本做界面和可用性验证，不把原型误称为可公开接单的生产版本。

首版交付是可直接阅读的学术调研报告和 PPT 逐页内容包（每页上屏文字、配图建议与图源、专业答辩式讲稿），不要求自动装配 PPTX。用户可能只想以较少时间完成课程或组会中的专业汇报；界面要让其无需学习提示词，也能选定适当范围、看懂进度、拿到并使用成果。

## 必须继承的已确认规则

1. 宽泛主题先给出少量清楚的收缩方向，由用户点击确认；系统不得代选。聚焦主题不强迫多走选择步骤。
2. 用户可免登录浏览首页、案例和输入主题；意图确认后、消耗完整生成费用前，使用邮箱一次性验证码登录。匿名草稿仅在当前页面内存中。每个已验证邮箱可领取一次完整快速版；深入版不在首次免费范围内。
3. 真实内测采用 EdgeOne 同域入口、扩展现有 Python 服务、独立 SCF 后台任务与托管 PostgreSQL；页面轮询真实任务阶段，完成后邮件通知并提供站内安全交付链接。交付文件保存 7 天，到期前 1 天提醒。支付暂缓。
4. 报告与 PPT 内容包应是客户可直接阅读的作品，不把 JSON、内部字段、任务编号或审计式标签放在正文显著位置。重要主张可追溯到真实来源；图源提供可点击的原文入口，许可未知时明确说明，不自动嵌入。
5. 费用和失败必须可审计。不要因追求低价统一降低推理质量；确定性格式问题优先本地修复，不能让失败调用反复收费。

上述第 2、3 条的机器可读唯一决策源是 `config/product-decisions.json`，解释见 `docs/免登录浏览与首次免费体验-产品工程决策框架.md`。改动这些已确认决策前必须取得用户同意。其他产品背景见 `README.md`、`docs/产品与使用场景.md`；功能状态见 `docs/产品剩余任务清单-2026-10-11.md`。

## 新界面的建议范围与验收

先设计并验证一条真实路径：免登录了解产品 → 输入主题与选择版本 → 如主题过宽则选择方向 → 确认题目与交付范围 → 邮箱验证闸门 → 查看真实任务阶段 → 阅读报告/PPT逐页内容 → 打开图源与下载。案例页可先使用上述满意样本；真实登录、免费资格、邮件、支付等未实现部分必须标为原型或待接入，不得用假完成状态误导。

验收时分别检查：新用户能否理解产品和版本差异；主题选择是否简洁且不会被系统代选；报告、PPT讲稿、来源和配图是否易读、易复制、易找到；手机与桌面布局是否清楚；等待/失败/证据不足/过期状态是否诚实；操作是否符合已确认的登录与首次免费规则。先完成可用性和视觉审查，再决定是否接入生产后台。

## 下一任务的工作顺序

1. 核对已确认决策、现有 `web/` 页面和真实内容样本；区分已实现、仅原型和未实现功能。
2. 提出页面地图、关键交互流程与视觉方向，先让用户选择或确认；避免初次使用要求过多决策。
3. 实现可交互的前端原型，沿用产品公共接口与状态，不另造脱离后台的专用流程。
4. 用宽题、聚焦题、任务失败、证据不足和过期交付测试桌面/手机体验；逐项修正。
5. 单独列出上线尚缺的后台、安全和运营条件，不将界面验收等同发布验收。
