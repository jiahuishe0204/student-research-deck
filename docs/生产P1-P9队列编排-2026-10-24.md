# 生产 P1—P9 队列编排

## 状态流

1. 登录用户创建任务，数据库原子预留一次体验额度并排入 P1。
2. P1 结果以 `{data, usage}` 保存；页面读取方向选项，用户确认后提交澄清文本。
3. P2 完成后，服务端执行现有多来源检索；智慧芽 MCP 仍只在第一条查询调用一次。
4. P3 只把 `keep` 来源扇出为 P4 作业；P4 全部成功后才汇总证据和图片。
5. P5—P9 使用现有 `WorkflowService` 和原有阶段契约顺序执行。
6. P9 成功后生成报告、PPT 内容和参考文献三类私有文件；全部通过 COS 完整性校验后才标记完成并消耗已预留额度。

## 费用与恢复边界

- 模型执行与阶段推进分别持久化。推进失败不会重新执行已经成功的模型调用。
- 模型作业最多尝试三次；编排推进也最多尝试三次。
- 最终失败时任务进入 `failed`，预留体验额度退回。
- `job_key` 唯一约束保证重复请求、SCF 重投和 P4 汇总不会重复创建下一阶段。
