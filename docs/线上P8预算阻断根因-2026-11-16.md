# 线上 P8 预算阻断根因

记录日期：2026-11-16  
调查对象：`TASK-70d2cf9a7ecf`，腾讯云函数 `research-task-worker-v2`，广州 `default` 命名空间，`$LATEST`

## 已确认根因

2026-11-14 的 P8 失败不是邮箱登录故障，也不是模型生成内容失败。腾讯云 SCF 日志在失败时段直接记录：

> `TASK_WORKER_ERROR ModelBudgetExceeded: 任务下一次请求将超过共享总 Tokens 上限 3000000`

查询时间为北京时间 2026-11-14 13:05—14:25，覆盖 Neon 作业表中最早至最晚的失败时间。此前仅查 14:00—14:25 的日志漏掉了前段，不能据此认定日志里没有根因。

Neon 对应任务的用量账本显示：

- 已结算实际 Tokens：2,920,087
- 仍保留的 Tokens：75,368
- 合计计入预算：2,995,455
- 任务上限：3,000,000
- 当时剩余预算：约 4,545 Tokens

该错误文本表明下一次 P8 请求在共享 Tokens 预算预留处被拒绝。当前仓库中同名异常的检查位于模型 HTTP 请求之前，与“未发出该次模型请求”一致；账本费用约 ¥9.085，云端费用上限为 ¥10。日志明确给出了预算类别和 300 万上限，因此费用上限不是这次异常的触发项。由于尚未取得线上运行包 SHA，这条源码路径交叉核对不能替代线上部署制品同一性的证明。

据 2026-11-16 只读查询记录，Neon 中共 41 条 P8 作业：24 条成功，17 条以 `permanent_failed` 结束；这 17 条的持久化错误码都是 `ModelBudgetExceeded`，作业尝试次数都是 3。失败窗口的 SCF 日志能看到同一总 Tokens 错误在重试中重复出现。结合当前仓库实现，预算预留拒绝发生在模型 HTTP 请求之前，因此这三次队列尝试没有新增付费模型请求；这不代表网络、服务端或格式失败的重试都不计费。

云函数当前环境显示 `MODEL_TASK_MAX_TOTAL_TOKENS=3000000`、`MODEL_TASK_MAX_COST_CNY=10`。三个独立的 Pro 限制变量未配置；但日志已经确认本次触发的是共享任务总 Tokens 上限。

## 影响上线的规则与实现问题

仓库中的《P8动态路由与成本保护规则》要求请求发出前保守预留任务 Tokens，并在超限时停止。这条硬限制本身正常工作，避免了超出已批准预算的模型调用。

需要修复的是错误处理：当前仓库中的生产 Worker 对作业执行中抛出的异常未按类型区分；只要当前 attempt 小于 3，就会按同一路径安排下一次尝试。预算超限是确定性阻断，重试不会改变预算，却会再次领取作业并再次报错。预算类异常应该进入可识别的预算暂停状态，保留已完成批次，等待预算或任务范围由产品决策处理；不能把预算暂停当作普通可重试失败。线上运行包 SHA 尚未确认，因此以上代码行为是仓库实现与日志相符的交叉证据，不是部署包同一性证明。

文档的 P8 规则限制的是模型调用层“最多一次付费重试”；当前仓库模型客户端按初次调用加最多一次重试执行。该规则没有覆盖队列层对整个作业的重试。当前仓库 Worker 又未按异常类型区分，导致预算预留拒绝仍被队列重复领取。本次确认的是队列调度与状态语义问题，没有证据表明发生了额外付费模型重试。文档应补充：预算预留拒绝不发起模型调用、不得自动重试；恢复时复用成功检查点，只处理未完成项，并留下明确的人工恢复记录。

## 对当前任务的处理边界

- 不重新运行任务，不重复生成已成功的 24 个批次。
- 不修改 300 万 Tokens 或 ¥10 上限，不释放 75,368 个仍保留的 Tokens。只有能证明对应请求没有发出时，才可以评估释放保留额；本次失败日志只能证明失败批次的预算拒绝发生在模型调用之前，不能单独证明账本中全部保留额都属于这些拒绝。
- 现有 17 个失败批次在当前 300 万上限下不能通过原请求预留。要完成剩余核验和 P9，必须在不丢失质量与范围的前提下重新评估剩余任务预算；预算是否提高由用户决定。
- 线上环境变量已查阅，但尚未独立取得运行包 SHA 并与 GitHub 生产分支对齐。因此本地源代码或文档变化不能视为线上修复或已发布版本。

## 后续修复方案

1. 在代码和持久化状态中区分 `budget_blocked` 与普通失败：不自动重试，不将整项任务误标为普通故障，不清除已成功检查点。
2. 记录稳定、无敏感信息的预算拒绝原因（例如 `task_total_tokens`），并保留 SCF 原因日志与任务、阶段、作业、尝试的关联标识。
3. 校准队列失败次数与 P8 重试政策：预算拒绝零重试；模型请求只在文档允许的情形下最多一次付费重试。
4. 对齐文档、决策记录、部署分支和运行包 SHA；部署前先在本地做对应回归，未经批准不改线上环境变量或数据库作业状态。

## 证据等级

- **已确认**：SCF 原始错误消息明确指向共享总 Tokens 上限 3,000,000；2026-11-16 的 Neon 只读查询记录显示 17 个失败作业的类别、终态和尝试次数；环境变量显示任务 Tokens 与费用上限。
- **计算结果**：账本已实际用量与预留量合计 2,995,455，距 3,000,000 约 4,545 Tokens。
- **仍未证明**：75,368 个预留 Tokens 分别对应哪些模型请求；线上运行包的精确提交/制品 SHA；调整任务预算后完成剩余 P8 所需的准确 Tokens 与费用。
